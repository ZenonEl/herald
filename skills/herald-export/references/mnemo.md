# Optional Mnemo handoff

Use this workflow when the user says `in Mnemo` or `в Mnemo`, or trusted project instructions explicitly select Mnemo for `herald-export`.

1. Before exporting, find the existing Mnemo archive for the selected project. Verify its identity and that its files are excluded and untracked or outside Git. Load the installed `mnemo:chat-export` and `mnemo:reconcile` skills and locate their importer and verifier. If the archive or tools are unavailable, report the blocker. The standalone export remains available.
2. For each Herald bundle, run the Mnemo importer in plan mode, apply the valid import and verify the archive. Keep attachments, replies and missing-file records through the native parser. Preserve the bundle if import or verification fails.
3. Match the bundle against verified package `herald_keys` and the current source records. Acknowledge with `inbox_done` and the corresponding `ctx:<archive-slug>#<package-id>` only when the exact `(chat_id, message_id)` and its source material are still archived. For earlier packages, verify that the source record still exists and match SHA-256 hashes of any attachment bytes in the current bundle against the archived attachments for those messages. A duplicate count, text match, or historical key alone is insufficient. If Herald reports `files_missing` for an export copy, leave affected keys unacknowledged until recovered. If you cannot isolate the affected keys, leave the bundle unacknowledged. An attachment never captured can be acknowledged once its missing-file record is verified in Mnemo. Report unresolved rows and keep their bundle.
4. Follow `mnemo:reconcile` to prepare and validate a review plan for this pass's verified packages. Apply the plan after the confirmation Mnemo requires. Report package references and concrete decisions, conflicts or questions.

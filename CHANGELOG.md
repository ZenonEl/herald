# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [0.6.0] — 2026-08-14

### Добавлено

- MCP-команда `send_client_copy` для текста, который можно переслать клиенту без переписывания;
- динамические заголовки из реальных тем сообщения клиента или проекта;
- проверка, запрещающая служебные заголовки `Проблемы`, `Нужно решить` и `Вопросы`;
- отдельные факты и один необходимый вопрос для каждой темы;
- отсутствие произвольного лимита слов и пунктов; действует только лимит Telegram.

### Изменено

- `send_client_copy` стал дефолтом skill для клиентских сообщений;
- `send_update` оставлен для явно внутренних отчётов.

## [0.5.3] — 2026-08-14

### Исправлено

- добавлены пары примеров «как не надо» и «как надо» для разных типов проектов;
- перед вопросом определяется цепочка зависимостей и выбирается первый нерешённый шаг;
- клиентский текст обращается к получателю напрямую вместо внутренних формулировок о нём;
- вопросы для следующих этапов и вопросы для заполнения раздела явно запрещены.

## [0.5.2] — 2026-08-14

### Исправлено

- тема запроса стала жёсткой границей клиентского сообщения;
- связанные с другими задачами проблемы и вопросы исключаются;
- вопрос задаётся только владельцу ответа и только когда он блокирует ближайшее действие;
- вопросы о следующих этапах откладываются до решения текущей зависимости;
- уже известные ответы и вопросы для полноты раздела не отправляются.

## [0.5.1] — 2026-08-14

### Исправлено

- объяснения строятся вокруг конкретных объектов, а не рассуждений о вариантах;
- для каждого объекта сохраняются все нужные шаги, свойства, результаты и ограничения;
- краткость удаляет вводные, сравнения и обобщения, но не факты;
- объектные объяснения отправляются свободной структурой через `send_text` и не ограничиваются пятью статусными пунктами.

## [0.5.0] — 2026-08-14

### Изменено

- `brief` закреплён как режим по умолчанию во всех текстовых MCP-командах;
- краткий апдейт рассчитан на клиента без знания внутреннего контекста;
- профессиональный жаргон и внутренние названия заменяются их понятным клиенту смыслом;
- из дефолтного текста исключены хроника, тесты, ревью, инструменты и технические детали, не влияющие на решение;
- краткий апдейт ограничен пятью пунктами во всех разделах суммарно;
- заголовки краткого сообщения упрощены для прямой пересылки клиенту.
- уведомление о завершении больше не добавляет декоративный emoji.

## [0.4.0] — 2026-08-14

### Добавлено

- точная фильтрация захвата по Telegram forum topic;
- несколько топиков одной группы с отдельными slug;
- структурированный `reply_context`: родитель, точная цитата и внешний ответ;
- backfill непосредственного родителя и его вложения при новом ответе;
- совместимая миграция существующей SQLite-базы.

### Безопасность

- полный контекст родителя сохраняется только для разрешённых capture-target;
- из незарегистрированного топика остаётся только явно показанная цитата.

## [0.3.0] — 2026-08-13

### Добавлено

- первый публичный выпуск Herald;
- MCP-отправка текста и файлов в Telegram;
- пресеты сообщений и глобальный skill для ассистентов;
- локальный capture-буфер и экспорт для Mnemo;
- двойное лицензирование AGPL-3.0-or-later и CC BY-SA 4.0.
